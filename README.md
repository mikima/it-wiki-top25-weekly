# it-wiki-top25-weekly

The weekly ranking of the most viewed pages on Italian Wikipedia, from 2015 to
today: pageview data, a short description of why each page peaked, images and
license metadata, plus the scripts and the small static site that publish it.

It is both a **dataset** (one JSON file per ISO week) and the **toolchain**
that keeps it up to date: a weekly GitHub Action fetches the new week,
describes each entry with OpenAI and publishes the site from `docs/`.

The descriptions follow one idea: anchor in time the reason for the spike in
views (a death, a TV broadcast, a match, a release…). From 2015 to 2022 many of
them were written by hand on it.wikipedia
([Utente:Mikima/Top25](https://it.wikipedia.org/wiki/Utente:Mikima/Top25/2015-48));
those are imported here and never overwritten.

## What is where

| Path | What it contains | Published on the site |
| --- | --- | --- |
| `docs/json/YYYY-WW.json` | **Main dataset.** One file per ISO week (2015-27 → today): top 25–30 pages with views, daily views, description, image, license. Schema below. | yes |
| `docs/rawjson/YYYY-WW.json` | Full weekly ranking before filtering and top-N cut (~2,500–3,000 pages per week: `rank`, `article`, `views`). Used to reconcile and backfill. | yes (not used by the page) |
| `context/YYYY-WW.json` | What OpenAI saw for each description: Wikipedia summary and Google News items of that week, with date and model. Google News results change over time, so this is the only record. Saved from November 2026 on. | no |
| `archive/wiki_manual/descrizioni_manuali.xlsx` | Archive of the hand-written descriptions from the it.wikipedia user pages (wikitext with links, plain text, week reconciliation). | no |
| `archive/wiki_manual/raw/*.wiki` | Raw wikitext of those 183 user pages, as downloaded. | no |
| `docs/week.html`, `week.css`, `week.js` | The weekly site (static, hand-written). | yes |
| `docs/index.html`, `docs/weeks.json` | Redirect to the latest week and list of available weeks (generated by `render_html.py`). | yes |
| `agent-instructions.md` | The prompt used by OpenAI to write descriptions (Italian). | no |
| `agent-notes.md` | Notes for people or coding agents editing the data by hand. | no |
| `editor/`, `editor.py` | Local visual editor for descriptions and images. | no |
| `assets/` | Category lists and stopwords used only by the legacy script. | no |

### Weekly JSON (`docs/json/YYYY-WW.json`)

Top level: `project`, `access`, `year`, `week` (ISO), `start_date`, `end_date`,
`days`, `total_articles` (pages in the full ranking) and `articles`. Weeks with
missing daily data also have `complete`, `available_days`, `missing_days`.

Each item in `articles`:

| Field | Meaning |
| --- | --- |
| `rank`, `article`, `views` | Position, page title (with underscores), weekly views |
| `daily_views` | `[{date, views}]` for the seven days; `0` can also mean "outside the daily top list" |
| `article_url`, `google_news_url`, `pageviews_url` | Helper links |
| `description` | Short Italian text explaining the spike (plain text, no links) |
| `description_source` | `manual` (hand-written, never rewritten), `openai`, `wikidata` (short Wikidata snippet), or empty |
| `description_model` | OpenAI model, when known (descriptions written before November 2026 don't have it) |
| `image_filename`, `image_url`, `image_commons_url` | Image on Wikimedia Commons and its thumbnail |
| `image_license`, `image_copyrighted` | License metadata from Commons |
| `image_artist`, `image_license_url` | Author and license URL (images chosen by hand in the editor) |
| `image_source` | `manual` when the image was chosen in the editor (kept when the week is regenerated) |
| `image_focus` | `{x, y}` in % of the image: the point to keep in frame |
| `image_crop`, `image_aspect` | Large views only: 0 = whole height visible … 100 = whole width; `image_aspect` is width/height |
| `image_fit` | Older framing mode (`width` / `height`), still supported |

### Context (`context/YYYY-WW.json`)

`{week, start_date, end_date, articles: {Title: {fetched_at, model, wikipedia_summary, news: [{title, source, pubDate, description}]}}}`.
News come from the Google News RSS search restricted to the week with
`after:` / `before:`, so they work for past years too (with fewer results the
further back you go).

## Weekly automation (GitHub Actions)

- **Aggiornamento settimanale** (`weekly-update.yml`): every Monday at 10:00
  UTC, with a second attempt at 16:00, fetches the week that just ended,
  writes the descriptions with OpenAI, refreshes `weeks.json` and commits
  `docs/` and `context/`. Can also be run by hand for a given week.
- **Descrizioni OpenAI (manuale)** (`enrich-descriptions.yml`): run by hand to
  (re)describe one or more weeks, optionally the same week in all previous
  years. Default mode `wikidata`.

Both need the `OPENAI_API_KEY` secret. The model comes from the repository
variable `OPENAI_MODEL` (currently `gpt-6.1-terra`); calls use the cheaper
**flex** tier by default.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Put the OpenAI key in `.env` (ignored by git): `OPENAI_API_KEY=sk-...`.

## Scripts

| Script | Purpose |
| --- | --- |
| `wiki-get-top-weekly-pages.py` | Fetch one ISO week, enrich it and write `docs/json` + `docs/rawjson`. Regenerating a week keeps manual descriptions, hand-picked images and framing. |
| `enrich_descriptions_openai.py` | Write descriptions with OpenAI using `agent-instructions.md`; saves the context in `context/`. |
| `editor.py` + `editor/` | Local editor: descriptions, image framing, images from Commons with license check, news used by the model. |
| `render_html.py` | Refresh `docs/index.html` and `docs/weeks.json`. |
| `backfill_weeks.py` | Run the fetcher backwards over many weeks; writes `backfill-report.json`. |
| `audit_missing_weeks.py` | Find gaps in `docs/json` and probe the API for missing days. |
| `import_manual_descriptions.py` | Import the hand-written descriptions from `Utente:Mikima/Top25/*` (re-runnable; `--dry-run` writes only the spreadsheet). |
| `backfill_description_sources.py` | One-off, already run: reconstructed `description_source` for older descriptions from git history. |
| `render_markdown.py`, `render_wikicode.py`, `render_utils.py` | Render one week as a Markdown or MediaWiki table (`markdown/`, `wikicode/`, not tracked). |
| `wiki-get-top-weekly-pages_old.py` | Legacy script kept for reference (uses `assets/` and `pageviewapi`). |

### Fetch one week

```bash
python3 wiki-get-top-weekly-pages.py --exclude-stopwords --format json --top 30 --year 2026 --week 12
```

Fetches the seven daily `top` endpoints of the Wikimedia REST API, aggregates
them, filters special pages (`--exclude-stopwords`), and adds daily views,
Wikidata descriptions (`description_source: wikidata`), page images, Commons
links and licenses. Writes `docs/rawjson/YYYY-WW.json` and
`docs/json/YYYY-WW.json`. Other options: `--allow-missing-days` (keep weeks
with missing days, tracked in the JSON), `--format csv`, `--output -`,
`--json-dir`, `--raw-json-dir`, `--thumbsize`.

### Descriptions with OpenAI

```bash
python3 enrich_descriptions_openai.py 2026-25 --dry-run          # what would change, no API calls
python3 enrich_descriptions_openai.py 2026-25                    # one week
python3 enrich_descriptions_openai.py 2026-21 --same-week-previous-years --mode wikidata
```

For each week the script sends one request with: the entries to describe,
their daily views and peak signals (peak day, share of the week,
`picco_isolato` for single-day spikes), the whole weekly ranking and the
previous week (to link entries and spot continuity), and for each entry the
Wikipedia summary and up to 10 Google News items of that week. It then checks
the answer: missing entries are asked again, and descriptions using vague
formulas ("citato nelle notizie", "al centro di articoli"…) are rewritten.
Manual descriptions are never selected or overwritten.

Options:

- `--mode`: `all` (default), `wikidata` (everything not written by OpenAI or by
  hand), `stubs` (short or empty), `missing` (empty only)
- `--model` (or `OPENAI_MODEL`): default `gpt-6.1-terra`
- `--service-tier` (or `OPENAI_SERVICE_TIER`): default `flex` (batch prices,
  slower; if OpenAI is busy the script waits and retries, then falls back to
  the standard tier)
- `--batch-size`: entries per request (default 30, a whole week)
- `--articles A B`: only some pages; `--max-news-items` (default 10);
  `--context-dir`; `--no-fetch-context`

At the end it prints tokens and an estimated cost; with `gpt-6.1-terra` on flex
a week costs about one or two cents. Files are written atomically, so an
interrupted run can simply be started again: weeks already done are skipped.

### Editor

```bash
python3 editor.py      # http://localhost:8766
```

- edit descriptions: saved as `manual`, so OpenAI won't touch them again;
- click the image to set the focus point, use the crop slider for the large
  views (0% whole height … 100% whole width) and preview hero, mobile sheet,
  desktop sheet and thumbnail;
- add or replace an image with a Wikimedia Commons link: the editor reads
  license, author and restrictions and flags licenses to double-check
  (non-free, NC, ND…);
- see the news and summary the model used, when saved in `context/`.

It refuses to overwrite a file changed by another program after it was opened
(for example while a description run is going). `--json-dir` and
`--context-dir` point it to copies for testing.

### Backfill, audit, rendering

```bash
python3 backfill_weeks.py --start-year 2026 --start-week 12 --min-year 2025 --max-weeks 20
python3 audit_missing_weeks.py --probe-week 2024-13
python3 render_markdown.py docs/json/2026-12.json      # markdown/2026-12.md
python3 render_wikicode.py docs/json/2026-12.json      # wikicode/2026-12.wiki
python3 render_html.py                                 # docs/index.html, docs/weeks.json
```

`backfill_weeks.py` walks backwards week by week with `--allow-missing-days`,
skipping complete weeks and retrying incomplete ones (`--dry-run`,
`--force-rewrite`, `--stop-on-error`). `audit_missing_weeks.py` lists gaps in
`docs/json` and shows which days the API returns as missing.

## The site

`docs/` is published with GitHub Pages. `week.html` reads `weeks.json` and
`json/YYYY-WW.json` at runtime. URL parameters: `?week=YYYY-WW`,
`&view=cmp&vs=YYYY-WW` (compare two weeks), `#Article_name` (open one entry).

## Notes

- Everything uses ISO weeks.
- The hand-written pages on it.wikipedia were named by hand and are sometimes
  one week off; `import_manual_descriptions.py` matches them to the right ISO
  week by comparing titles and views (see the `settimane` sheet of the
  spreadsheet).
- Some historical days are missing from the Wikimedia API (`404`); those weeks
  carry `missing_days`.
- The UI and the descriptions are in Italian; this README is in English.
