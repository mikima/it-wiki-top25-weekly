# it-wiki-top25-weekly

Python scripts to collect weekly top pageviews from Italian Wikipedia, enrich
them with metadata, and publish the results as JSON, Markdown, Wikicode, and a
small static HTML site.

## What This Repository Does

The project is built around a simple workflow:

1. fetch one ISO week of pageview data from the Wikimedia REST API
2. enrich the weekly ranking with article descriptions, page images, Commons
   links, and license metadata
3. save both a raw weekly dump and an enriched weekly JSON file
4. render that JSON into Markdown, Wikicode, and a browsable `docs/` site
5. backfill historical weeks and audit gaps when the upstream API is incomplete

The primary target is `it.wikipedia`.

## Requirements

- Python 3
- the dependencies in `requirements.txt`

Setup:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Repository Outputs

These directories and files are generated by the scripts in this repository:

- `docs/json/YYYY-WW.json`: enriched weekly output, limited by `--top/--limit`
- `docs/rawjson/YYYY-WW.json`: raw weekly ranking before enrichment and before
  the top-N limit is applied
- `markdown/YYYY-WW.md`: Markdown table generated from one weekly JSON file
- `wikicode/YYYY-WW.wiki`: MediaWiki table generated from one weekly JSON file
- `docs/week.html`, `docs/week.css`, `docs/week.js`: static weekly page (hand-edited, not generated)
- `docs/index.html`: redirect page that opens the latest available week
- `docs/weeks.json`: sorted list of available `YYYY-WW` week ids
- `backfill-report.json`: summary produced by `backfill_weeks.py`

## Script Overview

| Script | Purpose | Typical Output |
| --- | --- | --- |
| `wiki-get-top-weekly-pages.py` | Fetch and enrich one ISO week | `docs/json`, `docs/rawjson`, or CSV |
| `enrich_descriptions_openai.py` | Rewrite weekly descriptions with the OpenAI API and `agent-instructions.md` | updates `docs/json/YYYY-WW.json` |
| `backfill_weeks.py` | Run the weekly fetcher backwards across many weeks | JSON files plus `backfill-report.json` |
| `audit_missing_weeks.py` | Audit gaps in weekly JSON files and probe missing weeks | terminal report |
| `render_markdown.py` | Render one weekly JSON file as a Markdown table | `markdown/YYYY-WW.md` |
| `render_wikicode.py` | Render one weekly JSON file as MediaWiki/Wikicode | `wikicode/YYYY-WW.wiki` |
| `render_html.py` | Refresh the week index and redirect page for the docs site | `docs/index.html`, `docs/weeks.json` |
| `render_utils.py` | Shared utility functions used by the renderers | internal helper, no standalone CLI |
| `wiki-get-top-weekly-pages_old.py` | Legacy historical script kept for reference | not recommended for current use |

## Fetch One Week

Use `wiki-get-top-weekly-pages.py` when you want to generate data for one ISO
week.

Example:

```bash
python3 wiki-get-top-weekly-pages.py \
  --exclude-stopwords \
  --format json \
  --top 30 \
  --year 2026 \
  --week 12
```

This script:

- fetches the seven daily `top` endpoint responses for the requested ISO week
- aggregates them into a weekly ranking
- optionally filters stopwords and special pages
- enriches the top rows with:
  - article descriptions from MediaWiki `pageterms`
  - image filename and thumbnail URL from `pageimages`
  - Commons file URL
  - Commons license and copyright metadata
- adds per-article `daily_views`
- adds helper links such as `google_news_url`, `pageviews_url`, and
  `article_url`

Important options:

- `--year` and `--week`: required ISO year and ISO week number
- `--top` or `--limit`: number of ranked articles kept in the enriched output
- `--exclude-stopwords`: remove `Pagina_principale`, `load.php`, and pages in
  namespaces such as `Wikipedia:`, `Speciale:`, `File:`, and `Categoria:`
- `--format json`: write JSON output
- `--format csv`: write CSV output instead
- `--output -`: print the enriched output to stdout
- `--json-dir`: choose where enriched JSON files are written
- `--raw-json-dir`: choose where raw JSON files are written
- `--thumbsize`: thumbnail size used for page images
- `--allow-missing-days`: keep the week even if some daily top endpoints return
  `404`

When `--format json` is used, the script writes two files:

- `docs/rawjson/YYYY-WW.json`
- `docs/json/YYYY-WW.json`

When `--allow-missing-days` is enabled, the JSON output also includes:

- `complete`: `true` when all seven daily endpoints were available
- `available_days`: the days that were successfully fetched
- `missing_days`: a list of missing daily endpoints with date, status, and
  error detail

## Enrich Descriptions With OpenAI

Use `enrich_descriptions_openai.py` to update `articles[*].description` in one
or more weekly JSON files using the rules in `agent-instructions.md`. Before
calling OpenAI, the script fetches Italian Wikipedia summary context and Google
News RSS titles for the selected week, then passes that context to the model.

Set your API key in the local `.env` file, which is ignored by git:

```bash
OPENAI_API_KEY=sk-...
```

Preview what would be processed, without spending API credits or writing files:

```bash
python3 enrich_descriptions_openai.py 2026-25 --dry-run
```

Update one week:

```bash
python3 enrich_descriptions_openai.py 2026-25
```

Update multiple weeks in one run:

```bash
python3 enrich_descriptions_openai.py 2026-22 2026-24 2026-25
```

Update the same ISO week in previous years, skipping files that do not need work
for the selected mode:

```bash
python3 enrich_descriptions_openai.py 2026-21 \
  --same-week-previous-years \
  --min-year 2015
```

Useful options:

- `--mode all`: default; rewrites every description in the selected files.
- `--mode stubs`: updates blank descriptions and short MediaWiki-style stub
  descriptions.
- `--mode missing`: updates only blank descriptions.
- `--force`: alias for `--mode all`.
- `--articles Jannik_Sinner Lucrezia_Borgia`: limit the run to specific pages.
- `--batch-size 10`: control how many articles are sent per OpenAI request.
- `--model MODEL`: override the model, or set `OPENAI_MODEL`.
- `--no-fetch-context`: call OpenAI with only the JSON fields and links.

The script validates the JSON after writing and changes no fields other than
`description`.

CSV example:

```bash
python3 wiki-get-top-weekly-pages.py \
  --exclude-stopwords \
  --format csv \
  --top 50 \
  --year 2026 \
  --week 12 \
  -o weekly_data.csv
```

## Backfill Historical Weeks

Use `backfill_weeks.py` to run the weekly fetcher repeatedly, moving backwards
one ISO week at a time.

Basic example:

```bash
python3 backfill_weeks.py
```

This script:

- starts from the current ISO week by default
- can start from any explicit `--start-year` and `--start-week`
- walks backwards week by week, including across year boundaries
- calls `wiki-get-top-weekly-pages.py` with `--allow-missing-days`
- skips a week only when:
  - the enriched JSON already exists
  - the raw JSON already exists
  - the enriched JSON has no recorded `missing_days`
- retries weeks with incomplete metadata, corrupted JSON, or missing raw JSON
- writes a run summary to `backfill-report.json`

Useful options:

- `--start-year` and `--start-week`: explicit starting ISO week
- `--min-year`: lower year bound for the backfill
- `--top`: top-N value passed to the fetcher
- `--max-weeks`: cap the number of weeks processed in one run
- `--json-dir`: enriched JSON directory to inspect and write
- `--raw-json-dir`: raw JSON directory to inspect and write
- `--report-file`: path for the run summary
- `--dry-run`: show commands without executing them
- `--force-rewrite`: ignore existing outputs and rerun everything
- `--stop-on-error`: abort immediately on the first hard failure

Example: backfill the last 20 ISO weeks from a known starting point.

```bash
python3 backfill_weeks.py \
  --start-year 2026 \
  --start-week 12 \
  --min-year 2025 \
  --max-weeks 20
```

The generated `backfill-report.json` includes:

- `failed_weeks`: weeks that still failed completely
- `incomplete_weeks`: weeks written with `missing_days`
- `retried_weeks`: weeks that were rerun because outputs were incomplete,
  unreadable, or partially missing

## Audit Missing Weeks

Use `audit_missing_weeks.py` to inspect gaps in a directory of weekly JSON
files.

Examples:

```bash
python3 audit_missing_weeks.py
python3 audit_missing_weeks.py --min-year 2010
python3 audit_missing_weeks.py --probe-week 2024-13
python3 audit_missing_weeks.py --probe-week 2024-13 --probe-week 2015-27
```

This script can:

- list missing weeks in `docs/json` or another directory
- compress consecutive gaps into ranges
- probe the Wikimedia API for specific missing weeks and show which days return
  `404` or another error

Useful options:

- `--json-dir`: directory to audit, default `docs/json`
- `--min-year`: audit from ISO week 1 of a specific year instead of starting
  from the first existing file
- `--probe-week YYYY-WW`: probe one or more missing weeks directly
- `--project`, `--access`, `--timeout`, `--user-agent`: probe settings

## Render Markdown

Use `render_markdown.py` to convert one weekly JSON file into a Markdown table.

Example:

```bash
python3 render_markdown.py docs/json/2026-12.json
```

By default it writes:

- `markdown/YYYY-WW.md`

Use stdout instead:

```bash
python3 render_markdown.py docs/json/2026-12.json -o -
```

The Markdown table includes:

- rank
- article name with link
- total views
- inline SVG daily trend chart
- image thumbnail
- Google News link
- description

## Render Wikicode

Use `render_wikicode.py` to generate a MediaWiki table from one weekly JSON
file.

Example:

```bash
python3 render_wikicode.py docs/json/2026-12.json
```

By default it writes:

- `wikicode/YYYY-WW.wiki`

Use stdout instead:

```bash
python3 render_wikicode.py docs/json/2026-12.json -o -
```

The generated output includes week navigation and a wiki table suitable for
publishing in a MediaWiki page.

## Build the HTML Site

Use `render_html.py` to refresh the list of available weeks in `docs/`.

Example:

```bash
python3 render_html.py
```

By default it reads:

- `docs/json/*.json`

and writes:

- `docs/index.html`
- `docs/weeks.json`

Useful options:

- `--json-dir`: source directory for weekly JSON files
- `--docs-dir`: destination directory for HTML output

The weekly page (`docs/week.html` + `week.css` + `week.js`) is static vanilla
HTML/CSS/JS and is not generated by this script. It reads `weeks.json` and the
requested `json/YYYY-WW.json` at runtime. URL parameters:

- `?week=YYYY-WW`: week to show (defaults to the latest in `weeks.json`)
- `&view=cmp&vs=YYYY-WW`: open the "Confronta" view against another week
- `#Article_name`: open the detail sheet for one article

## Notes and Caveats

- All scripts use ISO weeks, not calendar months.
- The fetcher depends on external Wikimedia APIs. Some historical days are not
  available and may return `404`.
- With `--allow-missing-days`, incomplete weeks are preserved instead of being
  dropped, and the missing dates are tracked in the JSON.
- The HTML UI text is currently in Italian because it is meant for the
  published site, even though this README is in English.
- `wiki-get-top-weekly-pages_old.py` is a legacy script and is not part of the
  current workflow.
